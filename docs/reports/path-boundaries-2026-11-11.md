# Path-flow boundary repair — 2026-11-11

Author: Jason Stys. The original full-main Python CodeQL analysis of source `6f0a2536dd6e6a9b481a3f74b31388dda74e976c` produced 29 `py/path-injection` results even though the PR scan and open-alert query had shown no results. Publication was held. A successful workflow or an empty alert query was not treated as full-source clearance.

The reviewed flows crossed five actual roots: trusted legacy runtime selection, selected dataset inputs, selected model directories, registered dataset review, and stored image/glossary/job identities. Several existing guards were meaningful: authentication, private account imports-only forwarding, exact store lookup, normalized dataset identities and manifest/file fingerprints. They were not used as a blanket false-positive dismissal. The [official query guidance](https://codeql.github.com/codeql-query-help/python/py-path-injection/) recommends normalizing paths and checking an independent safe root before filesystem access.

The repair gives local selections independent launcher-owned component-safe grants, adds canonical UUID32 checks before lookups, derives fixed workspace artifact locations, and admits bounded regular-file descriptors. JSON/ZIP/caption/image/checkpoint readers share actual file-type/link/byte admission; image decoding uses the admitted bytes. Private imports-only behavior and runtime denial remain intact. Privileged legacy selection remains available with explicitly configured roots. Worker output registration now accepts only the original fixed authored artifact names. No query exclusion, suppression, custom analysis barrier, global filesystem-root grant, test deadline or original ML oracle was added.

New tests drive actual HTTP/grants/files and use actual descriptor replacement/growth and hardlinks; the FIFO test is explicitly POSIX-only. The first full development run passed 293 tests with one POSIX-only Windows skip and exposed one original JSON error-contract mismatch. The source was corrected to retain the original limit/regular-file errors; that failed run remains historical rather than being relabeled. The final frozen-source local run then passed all 296 tests with one explicit POSIX-only FIFO skip on Windows, including the original actual ML/private/native tests. Statement coverage was 83.07% across the whole source; no coverage floor or exclusion was changed. Ruff, three actual code-index error controls, exact 86-file AST indexes, TypeScript/UI build, pip consistency and all three installed browser-host probes passed. Exact hosted/native/full-main results remain separate required observations before publication.

See [usage, compatibility and limits](../local-path-boundaries.md). Version 0.3.1 remains unreleased while these gates are pending. Static alias checks are not protection against an actively racing same-OS adversary, and owner-selected Python executables are not authenticated by their basename.
